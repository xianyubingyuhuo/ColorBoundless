## 数据落库与处理策略

本项目采用“原始下载层 → 规范化数据层 → 知识库层 → 训练/检索层”的分层设计，目的是让数据既保留来源真实性，又能在后续训练中稳定使用。

### 1. 数据分层原则

- 原始下载层：只保留来源数据，不做业务逻辑判断。
- 规范化数据层：统一字段、统一色彩空间、统一标签体系。
- 事实知识库层：抽取语义规则、色板、风格模板、CVD 安全规则。
- 模型训练层：对不同数据源分别做特征提取、分类、排序或 embedding。

### 2. 数据源归类

1. 基础色彩库
   - 适用来源：RGB 色卡数据
   - 落库目标：建立统一的 HEX / RGB / Lab / HSL 索引
   - 关键任务：去重、有效性过滤、颜色空间转换

2. 肤色与底妆库
   - 适用来源：肤色数据集、化妆品色号数据
   - 落库目标：建立 undertone / Fitzpatrick / 亮度 / 深浅分类
   - 关键任务：标准化标签，生成皮肤-底妆映射关系

3. 时尚风格与推荐数据
   - 适用来源：推荐 CSV、时尚风格数据
   - 落库目标：构建 style、occasion、color pairing 的索引
   - 关键任务：风格编码、标签清洗、推荐排序

4. 视觉妆容数据
   - 适用来源：人脸妆容图像、检测数据
   - 落库目标：建立视觉样本与妆容属性映射
   - 关键任务：人脸裁剪、质量过滤、标签标准化

5. CVD 与可访问性数据
   - 适用来源：色盲模拟与对比性测试数据
   - 落库目标：建立可读性与安全阈值规则
   - 关键任务：模拟失色、计算对比度，生成安全性评分

### 3. 落库节奏

建议按四步执行：

1. 先落基础数据：RGB + 肤色 + 风格表
2. 再抽知识规则：配色规则、CVD 规则、风格模板
3. 最后做视觉样本：筛出高质量妆容图，用于检索与示例增强
4. 最后上线 RAG 与向量库

这能避免“先做大图训练、再补知识库”的低效路径。

## 一、项目定位

ColorBoundless 的目标，不是仅仅为“色盲用户”做一个单一的色号筛选功能，而是构建一套面向真实美妆场景的包容型色彩推荐与可视化系统：

- 让色盲 / 视障 / 低对比感知困难人群也能更自然地感知美妆效果
- 让不同肤色、不同审美偏好、不同妆容风格的人都得到更公平的推荐
- 让美妆不再被“主流颜色”一刀切，而是支持更丰富的非主流搭配、渐变妆容、冷暖对比、视觉层次与风格化表达
- 将“科学颜色逻辑”下沉到算法层，而把“语言解释、审美建议、个性化推荐”留给 LLM 层

这意味着我们的系统并非一个简单的“口红搜索工具”，而是一个“多品类色彩与美学智能推荐引擎”。

---

## 二、产品愿景：从“可见”走向“可感知、可选择、可创造”

美妆场景本身就是复杂的色彩世界：

- 口红不一定只有经典正红，很多人会选择紫色、莓红、深褐、冷色系、偏酒红、霓虹系调
- 眉妆不仅仅是单一颜色，渐变眉、雾眉、眉色过渡、冷暖分层都在现实中存在
- 粉底不只是肤色匹配，还涉及明度、黄皮/红皮/深色皮肤 undertone、遮瑕层次和自然质感
- 眼妆、腮红、眼影、修容、发色等都属于同一套色彩逻辑

因此，ColorBoundless 必须支持：

- 主流颜色与非主流颜色并行
- 经典配色与实验性配色并行
- 传统美学与科学色彩搭配并行
- 视觉直观与 CVD 友好设计并行

---

## 三、核心设计原则

### 1. 颜色不是“只看HEX”，而是看“结构与感觉”

我们不把颜色简单处理成一个 16 进制值，而是用 Lab / LCh / HSV / HSL 等空间去分析：

- 色相（Hue）
- 饱和度（Saturation）
- 明度（Lightness / Value）
- 冷暖属性（Warm/Cool undertone）
- 对比度与层次（Contrast / Separation）
- 适配场景（日常 / 晚宴 / 户外 / 拍摄 / 日系 / 复古 / avant-garde）

### 2. 科学美学优先，而不是“看起来像就行”

真正好的配色需要满足：

- 互补 / 类似 / 三角 / 分裂互补等色彩关系
- 亮度差异平衡，不会显得一片“脏色”
- 饱和度控制，避免过强刺激导致视觉疲劳
- 冷暖协调，避免看起来“杂乱”或“失真”
- 色彩在色盲模拟下仍能保有识别性

### 3. 保存“非主流风格”，而不是限制于安全配色

这也是本项目应体现的关键：

- 紫红口红、青紫、冷调玫瑰、酒红、青棕系、烟灰紫等并非“错误色”，它们属于审美表达
- 渐变眉、柔焦刷法、过渡层次的眉色都需要融入推荐逻辑
- 视障友好设计不等于“让所有人都只能看最中性的色彩”，而是让多样性在可理解的框架内被展示

---

## 四、系统架构设计

### 4.1 数据层：多源配色库

项目的核心不是单纯的口红库，而是构建一个多品类、可扩展的美妆配色知识库。推荐的数据来源包括：

1. 科学色彩理论库
   - Pantone Fashion Color Report
   - NCS / Munsell 色卡
   - Adobe Color
   - Coolors / Paletton
   - ColorBrewer

2. 美妆品牌色号库
   - MAC / Dior / Chanel / YSL / Fenty Beauty / Huda Beauty / Pat McGrath / Rare Beauty
   - 国内品牌：完美日记、花西子、欧莱雅、阿玛尼、香奈儿、植村秀等

3. 时尚与趋势库
   - Vogue / Harper's Bazaar / Elle 等时尚图鉴
   - Pinterest / Instagram 视觉趋势
   - 新发型、新妆容、各大品牌大片的 palette 抽取

4. 自建 “美妆配色数据库”
   - 每条记录包含：
     - hex / RGB / Lab
     - 色相类别：warm / cool / neutral / muted / vibrant
     - 适用品类：lip / brow / eyeshadow / blush / foundation
     - 适用场景：日常 / 约会 / 拍摄 / 晚宴 / 气质 / avant-garde
     - 风格标签：soft / bold / vintage / candy / smokey / editorial
     - CVD 安全评级
     - 可配颜色组合

### 4.2 视觉算法层

负责底层色彩处理，包括：

- Lab 空间转换
- CIEDE2000 色差计算
- CVD 模拟（Protanope / Deuteranope / Tritanope）
- 灰阶对比检测
- CLAHE / 对比增强 / 鲜明度保留
- 图像分割 + mask 生成
- 试妆渲染 / 色彩混合

### 4.3 美妆模块层

本项目的模块不只限于口红，未来建议纳入：

- lipstick：口红 / 唇彩 / 口红配色推荐
- eyebrow：渐变眉 / 雾眉 / 冷暖眉色组合
- eyeshadow：主色 + 辅色 + 高光色 / 眼妆搭配
- blush：腮红气色 / 面部层次 / 红润感
- foundation：底妆匹配 / 亮度与 undertone 调整
- overall look：整体妆容的和谐结构

### 4.4 Agent 层

LLM / Agent 层负责：

- 用户输入的语义理解
- 例如：『想要低调高级感、偏冷调小众紫』
- 生成适配建议语句：
  - 适合的色相区间
  - 推荐的搭配方式
  - 适合的肤色和妆感
  - 注意事项：避免过强对比、过度偏冷、遮盖感过重

但 Agent 不能脱离事实库。其输出应该由 RAG 检索到的知识、色卡数据库和风格规则共同支撑，否则容易产生明显的幻觉推荐。

### 4.5 RAG 知识增强层

为了避免美妆建议出现“看起来合理但其实不符合真实色彩规律”的情况，系统必须保留 RAG 层：

- 在用户提问时，先检索品牌色号与配色文档
- 再结合肤色、场景、色相、明度和 CVD 安全度筛选
- 最后由 Agent 生成自然语言解释，不直接凭模型记忆作决定

这部分是项目真正避免“美妆幻觉”的关键模块。

如果要做出真正的“特殊色彩搭配建议”，数据库不能只存一张口红表。需要从“色卡 + 配色 + 风格 + 适配性”四个维度建库。

## 六、特殊色彩搭配数据库从哪里找？

这是本项目非常关键的部分。很多人会把范围限制在“正红 / 玫红 / 枫叶红”，但这会把美妆的美学变窄。我们建议采用“多源融合”的方式：

### 1）色彩科学平台：作为底层颜色基础

这些平台提供最稳定的颜色理论库和色卡：

- Pantone Fashion Color Report：国际时尚流行色趋势
- NCS：自然色彩系统，偏科学与工程化
- Munsell：标准色相/明度/饱和度体系
- Adobe Color：可做配色方案生成
- Coolors / Paletton / ColorBrewer：配色结构分析

这些来源适合做：

- 基础色板
- 配色关系（类似 / 互补 / 分裂互补 / 三角）
- 色彩对比规则

### 2）美妆品牌官方色号库：作为“真实可售美妆色”数据

这是最贴近真实商业场景的数据来源：

- MAC、Dior、CHANEL、YSL、Fenty Beauty、Huda Beauty、Pat McGrath、Rare Beauty
- 国内品牌：花西子、完美日记、欧莱雅、阿玛尼、植村秀等

它们的优点：

- 颜色更接近真实产品
- 有明确的肤色适配与场景语义
- 可以形成一个“美妆产品色彩真实库”

### 3）时尚与大牌大片：作为“审美趋势基础”

如果想做出富有“拍摄感”“editorial感”“非主流美感”的搭配，不能只靠产品色卡：

- Vogue / Harper's Bazaar / Elle 视觉库
- 走秀、彩妆大片、品牌广告图
- Pinterest / Instagram / TikTok 视觉趋势
- 赛博妆、极简妆、anti-beauty、retro glam 等风格集

这些来源适合高层次的“风格抽样”，从图中提取：

- 主色 / 辅色 / 高光色 / 阴影色
- 视觉层次与饱和度
- 适合的肤色与整体妆感

### 4）自建像素级美妆配色数据库：最终落地核心

最有效的方案不是单独依赖某一个网站，而是做一个“自建美妆配色库”：

- 抽取大量美妆图中的颜色
- 标注色相/亮度/冷暖/风格
- 结合品牌官方色号与时尚趋势做统一整合
- 最终由算法筛选出最适合的搭配组合

这样才符合“科学颜色搭配美学 + 美妆真实场景”双重要求。

## 七、适合本项目的配色类型：从主流走向非主流

本项目不应只做“正红 / 玫红 / 奶茶色”。更应该覆盖：

- 紫色系口红：冷紫、酒紫、蓝紫、紫红、紫棕
- 非主流色彩：青铜绿、烟灰紫、深莓、冷玫瑰、棕中带紫
- 渐变眉：灰棕 → 暗紫 → 柔咖 → 谢幕褐
- 低饱和高级感：霜色灰、奶油粉、薄荷灰、冷棕
- 鲜明编辑风：深紫 + 亮珠光白 + 暗金
- 复古感：褐红 + 暗玫瑰 + 旧金

如果用户说“我想做一个高级感的冷紫口红搭配，带一点拍摄感”，传统数据库完全不够用，必须构建“非主流美妆色彩库”。

---

## 八、科学配色美学规则（推荐落地）

为了让搭配不只是“看着像”，建议在数据库中加入这些特征：

- 色相距离：类似色 / 互补色 / 三角色 / 分裂互补
- 明度平衡：主色与辅色不能完全同亮度
- 饱和度控制：主色强，辅色弱，避免喧宾夺主
- 颜色温度协调：冷红、冷紫、暖棕、暖金需要统一风格
- 皮肤相容性：衬托肤色而非冲突肤色
- 视觉层次：主色 / 过渡色 / 高光色必须分层

比如：

- 冷紫口红 + 柔冷灰棕腮红 + 奶白高光 = 高级冷感
- 深莓红口红 + 暖棕眼影 + 轻金亮片 = 典型夜场叙事
- 灰紫渐变眉 + 霜粉底 + 暖裸唇 = 轻奢高级感

## 十三、结论

ColorBoundless 的关键，不是“只做一个色盲友好模拟器”，而是构建一套“受色彩科学支撑、兼顾审美与包容性”的美妆色彩推荐系统。

它需要接受：

- 主流美妆与非主流美妆并重
- 经典配色与实验性搭配并重
- 视觉真实感与色盲友好性并重
- 美妆艺术性与科学可解释性并重

只有这样，数据库才真正能支撑起“特殊色彩搭配建议”，而不只是对一群主流色号做排序。
